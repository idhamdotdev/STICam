# Contributing to STICam

STICam's source code is private, so this repository does not accept code contributions.
It does actively want everything else.

## What helps most

### Bug reports

Open an [issue](https://github.com/idhamdotdev/STICam/issues/new/choose). A good report
includes:

- the STICam version, shown in the app;
- your Android device model and Android version;
- your Windows version and build;
- connection mode — Wi-Fi or USB;
- what you expected, and what happened instead;
- steps to reproduce it;
- a screenshot or short clip, if the problem is visual.

### Feature requests

Open an issue describing the problem you are trying to solve, not only the feature you
have in mind. Knowing the underlying need often leads to a better solution than the one
originally requested.

### Compatibility reports

STICam cannot be tested against every phone and PC combination. Reports that a specific
device works — or does not — are genuinely useful, especially for unusual camera
hardware.

### Security issues

Do **not** open a public issue. Follow [SECURITY.md](SECURITY.md), which uses GitHub's
private vulnerability reporting.

## What this repository does not accept

**Pull requests containing code.** The application source is not in this repository,
and code contributed by others would create shared copyright in a codebase that is
licensed commercially. Any code PR will be closed with a pointer to this file — this is
not a judgement of the code, it is a licensing constraint.

Documentation typo fixes are welcome as issues rather than pull requests.
